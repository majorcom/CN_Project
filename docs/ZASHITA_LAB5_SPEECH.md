# Текст для защиты (Lab 5 Redis Cache)

## Короткое выступление (1-2 минуты)

Я реализовал многоуровневое кэширование на Redis для ускорения API и снижения нагрузки на MySQL в проекте `mini-shop-server`.

Основная идея такая: на чтении система сначала смотрит в Redis, при промахе берет данные из БД, сериализует в JSON и кладет в кэш с TTL.  
На записи после успешного commit запускается инвалидация ключей, чтобы не отдавать устаревшие данные.

Конфигурация кэша и Redis вынесена в `app/config/setting.py` и `app/config/secure.py`.  
Ядро кэша находится в `app/core/cache.py`: там клиент Redis, декоратор `@cached`, сбор метрик hit/miss/error, шаблоны ключей и инвалидация.

Кэширование применено на DAO-уровне:
- `app/dao/product.py` (списки/детали/горячие товары),
- `app/dao/category.py`,
- `app/dao/banner.py`,
- `app/dao/user.py` и `app/core/token_auth.py` (данные пользователя для авторизации).

Инвалидация встроена в `app/core/db.py`: после `create/update/delete` вызывается `invalidate_for_model`.  
Очистка делается через `SCAN + UNLINK`, чтобы не блокировать Redis как при `KEYS *`.

Дополнительно реализовано:
- защита от cache stampede через single-flight lock (`app/core/cache.py`);
- прогрев кэша при старте (`app/core/cache_warmer.py`);
- админские CMS-эндпоинты для статистики и ручной очистки:
  - `GET /cms/cache/stats`,
  - `POST /cms/cache/flush`,
  - `POST /cms/cache/metrics/reset`
  в `app/api/cms/cache.py`.

Покрытие тестами:
- unit: `tests/test_cache_unit.py`,
- integration: `tests/test_cache_integration.py`.

Критерий ускорения проверяется скриптом `tools/bench_cache.py`, где сравниваются cold/warm сценарии (p50/p95).  
Цель — минимум 50% ускорение для кэшируемых путей.

Итог: система стала быстрее на горячих запросах, устойчивее к пиковым чтениям, и при недоступности Redis продолжает работать через БД (graceful degradation).

## Быстрые фразы для устных ответов

- **Почему DAO, а не route?**  
  Чтобы не дублировать кэш-логику между endpoint-ами и держать ее рядом с доступом к данным.

- **Что если Redis недоступен?**  
  Логируем ошибку и идем в БД; API не падает.

- **Как избегаете устаревших данных?**  
  Инвалидация сразу после commit по префиксам, связанным с моделью.

- **Почему не KEYS?**  
  `KEYS` блокирует Redis на больших наборах; используем `SCAN + UNLINK`.

- **Как доказали ускорение?**  
  Скриптом `tools/bench_cache.py`: сравнение cold/warm и p50/p95.
