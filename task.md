Задача: Реализация системы кэширования на базе Redis для оптимизации производительности API
Информация о проекте
Название: mini-shop-server

GitHub: https://github.com/Allen7D/mini-shop-server

Описание: Flask-based RESTful API backend для WeChat mini-programs с RBAC, управлением товарами, обработкой заказов и интеграцией платежей.

Технологии: Python 3.8+, Flask 2.0.3, SQLAlchemy, MySQL, Swagger/Flasgger

Описание задачи
Необходимо реализовать многоуровневую систему кэширования данных с использованием Redis для снижения нагрузки на базу данных MySQL и ускорения отклика API.

1. Интеграция Redis
Добавить конфигурацию подключения к Redis в app/config/secure.py и app/config/setting.py
Создать модуль для работы с Redis в app/core/cache.py с поддержкой операций: get, set, delete, expire, flush
Реализовать декоратор @cached для автоматического кэширования результатов функций
2. Кэширование данных
Кэшировать списки продуктов с пагинацией (TTL: 5 минут)
Кэшировать детальную информацию о продукте по ID (TTL: 10 минут)
Кэшировать категории и их иерархию (TTL: 30 минут)
Кэшировать активные баннеры (TTL: 15 минут)
Кэшировать данные пользователя при авторизации (TTL: 1 час)
3. Инвалидация кэша
Реализовать механизм инвалидации кэша при создании/обновлении/удалении данных в моделях
Создать паттерн ключей кэша для групповой инвалидации (например, products:list:*)
Интегрировать инвалидацию в DAO слой (create, update, delete методы)
Добавить ручную очистку кэша через CMS API для администраторов
4. Оптимизация запросов
Реализовать кэширование "горячих" данных (самые популярные продукты) с более длительным TTL
Добавить механизм "cache warming" - предварительную загрузку часто запрашиваемых данных при старте приложения
Реализовать защиту от "cache stampede" (одновременный доступ множества клиентов к истекшему кэшу)
5. Мониторинг и логирование
Добавить метрики попаданий в кэш (cache hit/miss ratio)
Логировать операции кэширования в существующую систему логов
Создать endpoint в CMS для просмотра статистики кэша
6. Тестирование
Написать unit-тесты для модуля кэширования
Добавить интеграционные тесты для проверки корректности инвалидации кэша
Протестировать работу системы при недоступности Redis (graceful degradation)
Проверить корректность работы при параллельных запросах
Критерии приемки
Все тесты проходят успешно
Время отклика API для кэшируемых endpoint-ов снижено минимум на 50%
Инвалидация кэша работает корректно (данные актуальны после изменений)
При недоступности Redis приложение продолжает работать с базой данных
Документация API (Swagger) обновлена с описанием особенностей кэширования
